### 🚦 Automated CI/CD Pipeline — Security-Integrated Delivery on Kubernetes
> **Jenkins · Groovy Shared Library · Terraform · Docker · Helm · SonarQube · Trivy · Dependabot · AWS ECR · AWS EKS · Jenkins Credentials · Quality Gates**

An end-to-end CI/CD system taking code from commit to a deployed workload on Kubernetes with security gates enforced at every real decision point. Nothing gets deployed unless it passes every quality, security, and reliability check along the way.

- 🧪 End-to-end CI/CD pipelines with integrated functional testing, static code analysis, API testing, SAST, and DAST — Jenkins delivery infrastructure (controller, dedicated agent node, SonarQube) provisioned via IaC and configured through automated userdata bootstrap scripts, replacing hours of manual VM setup with a single reproducible deployment
- 🔒 SonarQube static analysis stage that blocks pipeline progression on any quality gate failure, followed by container image build with version-tagged artifacts pushed to a private registry, and Trivy image scanning that halts deployment on any critical or high-severity CVE in the built image
- 🔐 Least-privilege secrets via centralized Jenkins credentials store with stage-scoped injection — `github-token`, `aws-cred`, `sonar-token`, `ssh-auth` each exposed only within the specific stage that needs it, minimizing blast radius
- ♻️ Reusable Groovy shared library centralizing CI/CD logic across the service portfolio, with parameterized workflows that provision environment-specific Kubernetes namespaces on demand and orchestrate rolling releases through Helm-based templating — eliminating per-service pipeline duplication that caused maintenance drift, and enabling changes to propagate across every service through a single library update

Previous-generation VM-based (non-container) platform running the same 10-service application on EC2. Fully self-bootstrapping from a single `terraform apply` on the bastion layer — provisions the entire platform end-to-end with zero manual intervention.

- 🚀 Self-bootstrapping Bastion with boot-time script that auto-triggers database and service layers on first boot — one command deploys the entire platform
- 🎯 Custom per-service Terraform module in a `for_each` loop drives the full pipeline for each service — EC2 provisioning, Ansible role execution, instance stop, AMI baking, Launch Template creation, Target Group setup, ASG with rolling deployment, CPU-based auto-scaling policy, ALB listener rule registration
- 📦 10 Ansible roles (one per service) with a shared `common` role for setup logic — secrets pulled from SSM at runtime via `amazon.aws.aws_ssm` lookup plugin, systemd and Nginx configs rendered from Jinja2 templates, zero credentials in playbooks
- 🌐 Internal ALB for backend service-to-service routing + public ALB for end-user traffic + CloudFront CDN with intelligent caching — all fronted by a wildcard ACM cert and enforced HTTPS
